## Source, disk and recording ownership

The local live buffer is opt-in and applies only to live channels in the built-in player. Defaults: disabled, 10 minutes, 512 MiB per source session. The user can choose 1–30 minutes and 64–4096 MiB; zero minutes disables the feature. Time and byte limits both evict old history. The quota includes incomplete payload files, not filesystem allocation overhead. Several sources held by recordings can coexist, each with its own quota; this is not a global disk budget.

`live_buffer.py` owns one FFmpeg input, a tokenized loopback HTTP receiver and a sliding MPEG-TS segment store. Compatible video, audio, subtitle and data tracks are copied, without transcoding, playback-rate manipulation or archive API calls. The receiver checks every write before disk allocation; an oversized segment fails instead of exceeding the payload quota. Metadata, file count, local HTTP workers and view cursors are bounded. Slow clients read small chunks with files closed before socket writes; they cannot pin an evicted Windows file indefinitely. Expired segment requests return 410. Read and upload tokens differ, and the listener binds only to 127.0.0.1. This is a local capability boundary, not protection against malicious software on the same machine.

Manifest and segment uploads can commit out of order: the latest manifest is replayed after segment commit; future unlisted files are retained, and missing intermediate files never become false contiguous sequence entries. Finite input waits for final uploads to drain. Sliding playlists do not claim EVENT retention. Their reload target stays fixed after initial establishment; a later unexpectedly long GOP fails visibly. Nominal segment time is two seconds but real keyframes determine startup/seek granularity and may delay the first picture. The ordinary saved VLC cache and existing Dispatcharr behavior are preserved.

`client_timeshift.py` serializes player-stop completion, old source retirement and new source startup off the GUI thread. Stale queued UI deliveries must acknowledge ownership or close their abandoned source before the next transition proceeds. An additional registry gate coordinates a scheduled recording's direct-vs-local input decision with new buffer registration. The known one-stream-provider check is repeated inside that gate. Local media probes are routed to the buffer, and advisory provider probes are preempted/suppressed.

`RecordingManager` acquires a lease and protected local live-edge cursor while retaining the original provider connection key and existing recording format/finalization logic. Repeated viewer seeks cannot evict that recording cursor. Player Stop or sleep expiry releases only the player owner; the recording keeps ingest alive. The last lease closes the source, local service and cache. A recording starts at the latest completed segment, not at the viewer's rewound position; a small GOP-dependent lead-in is possible. Enable buffering before recording: a pre-existing direct recording is not retrofitted. Disabling an actively shared buffer is refused. Casting requires stopping buffered local playback first.

For a recognized `.m3u8` master, bounded metadata reads select one variant before FFmpeg probing, observing a configured bitrate cap when possible. Separate URI-based rendition groups are refused to avoid silently dropping audio/subtitles. Unknown-extension masters, DRM, unusual protocols, every audio/subtitle codec and every provider policy are not certified. HLS naturally uses playlist/key/segment requests; “one owned input” is not a claim of a single TCP/HTTP connection for HLS. Exactly one provider GET is tested for the continuous TS fixture. Rewinds and recording reuse that source rather than opening another provider media input; reconnects can make sequential requests.

## Rewind and subtitles

Playback menu commands configure history, select seconds behind the newest completed picture, and return to that local live edge. Zero delay does not reopen the provider. The native clock contributes deltas after the first valid sample, avoiding double-counting nonzero absolute TS timestamps. Backward native clock rebasing preserves the logical position. Position accuracy remains limited by status polling and keyframes. A paused or running position that expires moves to the oldest retained segment with a status message. Ended finite input remains reviewable until its session is released.

Buffered jumps create a fresh normal subtitle session and clear stale file cues/speech ownership. Compatible embedded captions keep native media timing. External SRT/ASS/VTT loading is refused while buffered because no verified external-file zero-to-live-epoch mapping exists; direct playback retains its existing behavior. Unsupported remux codec warnings fail the buffer rather than claim transparent preservation. This does not add embedded live-caption extraction/TTS to libVLC, OCR, universal external-player timeshift, speech time stretching or guaranteed cue completion. No slowdown is introduced by a playback rate below 1, but network loss, decoder startup, insufficient history or disk contention can still pause playback.

## Sleep fade

The existing built-in 0–1440-minute timer now asks for a fade interval, default five seconds, maximum 300 seconds and no longer than the countdown. Zero disables fade. Both numeric dialogs must be accepted before replacing a running timer. The fade preference persists; an active countdown does not restart after application relaunch. Existing F1 help-topic routing is attached to the commands and dialogs.

A monotonic deadline remains authoritative. Generation guards reject stale UI callbacks and queued native volume writes. Fade ticks occur at most every 250 ms; only programme audio is scaled, with one status announcement. The slider/desired volume remains independent of attenuated native output. User volume changes during fade update that desired level. Cancellation and explicit manual Stop restore it, and next startup reapplies it even if a stopped audio output rejected the queued restoration. Ordinary channel changes, retries and buffer jumps preserve the window's timer; manual Stop/close cancel it. Recordings, the system mixer, screen readers, the separate subtitle speech output and external players are not faded. No computer sleep/shutdown action is added.

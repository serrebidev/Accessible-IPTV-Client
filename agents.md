## Project Overview

Project = Accessible IPTV Client, a wxPython GUI focused on playlist loading, EPG import/search/matching, accessible channel browsing, internal/external playback, casting, and Windows self-updates.

`main.py` creates the main frame, tray icon, playlist/EPG managers, channel/group/search UI, background playlist and EPG work, player launching, casting actions, and update checks. `options.py` owns config persistence, cache paths, database paths, and config normalization.

## Architecture

- **main.py**: Main wx frame (`IPTVClient`), tray restore behavior, playlist and EPG managers, channel list population, group filtering, search including EPG search, catch-up dialog, internal/external player launch, casting menu actions, and update prompts.
- **internal_player.py**: Built-in libVLC player with adaptive buffering, stream preflight checks, live/catch-up option handling, automatic reconnect logic, fullscreen (F11), play/pause/stop controls, accessible control names, and volume slider. Volume uses 2% normal steps and 5% Ctrl+Up/Down steps.
- **sitecustomize.py**: Compatibility shim only. It re-exports the canonical `InternalPlayerFrame` from `internal_player.py` and must not grow separate player logic.
- **playlist.py**: Playlist parsing plus XMLTV import/search/matching. The EPG database is SQLite in `tempfile.gettempdir()` via `options.get_db_path()`, uses WAL and busy timeouts, logs debug details to `iptvclient_epg_debug.log` in the temp directory, and handles XML/GZip downloads with resume plus HTTP 416 fallback.
- **channel_names.py**: Single source of truth for channel-name normalization and country/group detection (`STRIP_TAGS`, `NOISE_WORDS`, `group_synonyms`, `canonicalize_name`, `strip_noise_words`, `extract_group`). Stdlib-only and dependency-free so both `playlist.py` and `options.py` can import it without a cycle (`playlist` already imports `options`). `playlist.py` re-exports these names for existing callers. Never re-implement or copy these helpers into another module: the UI and the EPG database must normalize names identically or matching silently fails.
- **providers.py**: Xtream Codes and Stalker Portal clients for building playlist/EPG URLs, handling auth/session state, and surfacing `ProviderError`. `get_account_info()` on each client returns the provider's subscription record (`player_api.php` with no action for Xtream; `type=account_info&action=get_main_info` for Stalker).
- **account_info.py**: Provider account status (File > Account Info). wx-free: discovers accounts (configured providers plus accounts autodetected from `get.php?username=…` playlist URLs and `/live/USER/PASS/1234.ts` channel URLs), fetches them, and formats a flat `Label: value` report. The dialog itself is `main.AccountInfoDialog`.
- **options.py**: JSON config persistence. Reads portable/app, cwd, user config, and frozen `_MEIPASS` candidates; writes to the app/cwd path when possible and otherwise the user config path. Also provides cache path hashing, default config values, and config clamping. Name-normalization helpers live in `channel_names.py`, not here.
- **favorites.py**: Favorite-channel identity. Stdlib-only and wx-free: builds the provider-stable key a favorite is stored under, filters the playlist by those keys, and owns the `Favorites` category sentinel. Never key a favorite on the resolved stream URL.
- **user_guide.py** and **docs/help/<lang>.md**: the offline User Guide and F1 context help. `user_guide.py` is wx-free: it renders a small Markdown subset to plain text, splits it into sections by `{#topic-id}` heading anchors, picks the guide for `i18n.resolved_language()` and falls back to English (whole file, and per topic). `main.UserGuideDialog` shows it in one read-only `TE_RICH2` text box with a Topics list and Find. Controls and dialogs carry a `help_topic` (class attribute, `user_guide.set_help_topic`, or a callable for controls whose meaning changes); menu items are mapped with `user_guide.set_menu_help(owner, item_or_menu, topic)`. `tests/test_user_guide.py` fails when code asks for a topic `en.md` does not have. `main.spec`, `tools/build_deb.py` and `tools/release.py` all ship/verify `docs/help`.
- **power.py**: "Shut down when recording is finished". Stdlib-only and wx-free: the per-platform shutdown commands and the `should_shutdown` rule. `main.py` owns the menu item, the confirmation and the cancellable countdown.
- **casting.py**: Persistent background asyncio loop for cast operations. Supports Chromecast, DLNA/UPnP, and AirPlay when optional libraries are installed.
- **stream_proxy.py**: Local stream proxy for casting. Handles direct byte proxying, HLS remux/transcode, Chromecast-safe HLS output, radio/audio mode, Python-to-FFmpeg piping for provider auth headers, bootstrap HLS startup, and best-effort Windows Firewall rules.
- **updater.py**, **update_helper.ps1**: Windows packaged-app updater. The app starts the helper with Windows PowerShell directly (never through `cmd /c`, which splits a helper path containing a space) and grants it foreground rights so its status window and the installer's UAC prompt are really shown. Uses a GitHub release manifest, SHA-256 validation, Authenticode verification with pinned thumbprints, a fully silent helper launch (no console window) driven from an accessible `wx.ProgressDialog`, backup, rollback, and local config preservation. Every update subprocess goes through `updater.run_hidden`/`updater.popen_hidden` so nothing flashes a console.
`tools/smoke_favorites_shutdown.py` and `tools/smoke_virtual_list_nvda.py` are GUI smoke tools for the wx behaviour pytest cannot reach (menu items, virtual-list focus events, real libVLC construction). Run them after touching the channel list, the favorites category, the player's audio-track menu or the shutdown countdown.

- **main.spec**, **tools/release.py**, **build.bat**, **build_exe.bat**: Build and release pipeline. `build.bat` delegates to `build_exe.bat`; `build_exe.bat` delegates core work to `tools/release.py`.

## Config File (`iptvclient.conf`)

Important keys include `playlists`, `epgs`, `media_player`, `custom_player_path`, `internal_player_buffer_seconds`, `internal_player_max_buffer_seconds`, `internal_player_variant_max_mbps`, `epg_enabled`, `epg_auto_import_interval_hours`, `minimize_to_tray`, `show_player_on_enter`, `auto_check_updates`, `favorites`, `preferred_audio_tracks`, `prefer_audio_description`, and `shutdown_after_recordings`.

`favorites` is a list of `favorites.channel_key()` strings, `preferred_audio_tracks` a list of track-name/language keywords in priority order. Both are clamped by `options.normalize_channel_and_audio_settings()` on every load and save, so a hand-edited config cannot crash startup.

`iptvclient.conf` is user-local runtime configuration. Do not bundle a local repo `iptvclient.conf` into public releases.

## Casting

Casting is Caster's code (github.com/serrebidev/Caster), not a re-implementation. `caster_engine.py` (the GUI-free top of Caster's `caster.py`: probing, HLS relay, TsSource, Device), `caster_extras.py`, `caster_devices.py` and `caster_config.py` are generated by `python tools/sync_caster.py` from a Caster checkout (default `../Caster`). Never edit them here: fix Caster, then sync. `casting.py` is this app's replacement for Caster's `MainFrame` play/stop/recovery logic: Chromecast, AirPlay (RAOP audio, no pairing), UPnP/DLNA, Sonos, Roku and Kodi.

- Channel headers: the engine and receivers fetch URLs with their own headers, so a channel with headers goes through the stream proxy's `/g/` header gateway (`StreamProxy.get_gateway_url`). The gateway keeps the upstream path so relative playlist URIs resolve through it, and rewrites absolute ones.
- One-stream providers: pass `exclusive=True` to `CastingManager.play`; probing, codec detection and the relay then run one after another with `catchup_direct.settle_media_session()` between them.
- Speakers (Sonos, audio-only UPnP renderers) get a TV channel as MP3 through the proxy's audio path.
- Live tests (`tests/test_cast_live.py`, `IPTV_RUN_LIVE_CAST_TESTS=1`) may only target R&B Room (Cast name "RB Room").
- Debian: pyatv needs compiled modules, so the Architecture: all `.deb` cannot carry it. postinst builds `/usr/lib/accessible-iptv-client/venv` (`--system-site-packages`) and pip-installs the casting libraries; the launcher prefers that Python; postrm removes it. `tools/deb_smoke_test.sh` checks it.

## Internationalization (i18n)

- **i18n.py** is a self-contained, standard-library-only (gettext) translation layer. It installs `_()`, `ngettext()` and `N_()` as Python builtins (the documented `gettext.install` idiom) so any module can call `_("text")`. Modules that use it also do `from i18n import gettext as _` at the top, both to keep static analysis happy and because the function consults the *currently active* catalogue on every call (so switching language at startup works without re-importing).
- User-facing strings throughout `main.py`, `internal_player.py`, `playlist.py`, `options.py`, `providers.py`, `updater.py`, and `external_player.py` are wrapped in `_()`. Dynamic text uses translatable templates with `.format()` (e.g. `_("Casting to {device}...").format(device=name)`) — never f-strings, because gettext/xgettext cannot extract an f-string.
- **`_` is also a throwaway/`lambda _:` parameter name all over this codebase.** That is fine in scopes that never call `_()`. Where a handler both takes a `_` parameter (or unpacks `url, _ = ...`) *and* needs to translate, the local was renamed (`_event`, `_unused`). If you add a `_()` call inside a function whose event/throwaway is named `_`, rename that local or you will call a non-callable.
- Strings that double as internal keys are NOT translated as keys: the `"All Channels"` group sentinel and the `media_player` config values (`"Built-in Player"`, `"Custom"`, brand names in `PLAYER_KEYS`) stay English internally; only their *display* is wrapped (`_(label)` in the menu, `_("All Channels")` in the group list, with `on_group_select` matching both the translated and English forms).
- **A deferred `_(variable)` still needs the msgid extracted.** `i18n.N_()` is the marker for that: it returns its argument unchanged (so the key stays English) but the extractor records the string, so the later `_(label)` has something to look up. `PLAYER_KEYS[0]` uses `N_("Built-in Player")` for exactly this reason — the other entries are brand names that are the same in every language. If you add another indirectly-translated key, wrap it in `N_()` or it will silently stay English in all catalogues.
- **No `wx.Locale`.** It flips the process `LC_NUMERIC`, which would break the `2.5`-style floats fed to libVLC options and config. Translate via gettext only; wx stock button labels (OK/Cancel) stay in wx's own language.
- Language preference lives in `iptvclient.conf` under `language` ("auto"/"en"/"hu"...), defaulted in `options.load_config`. `IPTVClient.__init__` calls `i18n.init_from_config(self.config)` *before* building the UI. The **Options > Language** submenu (built in both the Windows/macOS menubar and the Linux button-menu) writes the setting and prompts for a restart (existing menus/labels are not rebuilt live).
- Catalogues live under `locale/<lang>/LC_MESSAGES/iptvclient.{po,mo}` plus the `locale/iptvclient.pot` template. English is the source language (no catalogue needed — gettext returns the msgid). Thirteen catalogues ship fully translated (`i18n.SHIPPED_CATALOGS`): `es ar pt fr de ru tr it pl hi zh ja hu`.
- **`tools/i18n_tools.py`** is dependency-free tooling (pure-Python AST extractor + pure-Python `.mo` compiler — no GNU gettext/Babel/polib needed):
  - `python tools/i18n_tools.py extract` — rebuild `locale/iptvclient.pot` from `_()`/`gettext()`/`N_()`/`ngettext()` calls.
  - `python tools/i18n_tools.py update` — fold new POT strings into each existing `.po`, keeping translations.
  - `python tools/i18n_tools.py compile` — compile every `.po` → `.mo`.
  - `python tools/i18n_tools.py notes` — rebuild `locale/release_notes.pot` from the newest three CHANGELOG entries and fold it into every language's `release_notes.po` (may stay partly untranslated; see the release-notes learning below).
  - `all` — extract + update + notes + compile. After editing any `.po`, recompile; `tests/test_i18n.py::test_committed_mo_matches_po` fails if the committed `.mo` is stale, and `test_translation_placeholders_match_source` fails if a translation drops a `{token}`.
- **`main.spec` recompiles every `.po` → `.mo` at build time** (via `i18n_tools.cmd_compile()`) and bundles `locale/<lang>/LC_MESSAGES/*.mo` as datas, so a release can never ship a stale or missing catalogue. `i18n.locale_dir()` resolves to `sys._MEIPASS/locale` when frozen.
- To add a language: `python tools/i18n_tools.py update` to create/seed `locale/<code>/LC_MESSAGES/iptvclient.po` (or copy the `.pot`), translate the msgstrs, `compile`, then add `(code, "Native name")` to `i18n._LANGUAGE_LABELS` and `code` to `SHIPPED_CATALOGS`.

## Current Release Build Rules

- Use `build.bat release` for public releases. `build.bat` calls `build_exe.bat`, which calls `tools/release.py`; running `build.bat` with no argument performs a local build only.
- Each `release_notes.po` msgstr is that one language's text. v1.145.0 shipped two bullets whose msgstr in all 12 languages was the Python repr of a `{lang: text}` dict, so What's New read the whole table aloud; when filling translations by script, write `table[lang]`, never the table. `audit_notes` now rejects a msgstr shaped like a language table.
- Every release is gated by a translation audit of every shipped language except Hungarian (`tools/translation_audit.py`, exempt by the maintainer's request). `release.py release` runs `translation_audit.require_complete()` before it writes `app_meta.py` or `CHANGELOG.md`, and `dry-run` prints the same report. It fails on: an `iptvclient` string that is missing, empty, an English copy not listed in `locale/identical_ok.json`, or drops a `{placeholder}`; a `docs/help/<lang>.md` whose anchored sections or per-section bullet/paragraph counts differ from `en.md`, that still contains an English line, or whose `docs/help-sync.json` stamp (git blob id of `en.md`) is not the current `en.md`; an empty What's New bullet among the three releases the new version will show, including its own bullets. Workflow before releasing: `python tools/translation_audit.py` to see problems; after translating English guide changes (the failure prints the `git diff <old> <new>` of `en.md`), `python tools/translation_audit.py mark-help-synced <langs>`; commit everything; then `python tools/translation_audit.py prepare-notes` adds the upcoming release's bullets to each `release_notes.po`, translate them and run `build.bat release` **without committing them** (the release sync keeps them and the release commit stages `locale/`; committed extra msgids would fail `test_committed_notes_catalogues_cover_the_current_window`). Every commit, `chore:` included, becomes a bullet, so do not commit after `prepare-notes`.
- Starting the release from an agent shell: run `cmd /d /c "<repo>\build.bat release > <log> 2>&1"` from PowerShell, using the full path to `build.bat`. From Git Bash, `cmd //c "build.bat release"` opens an idle prompt, builds nothing and still exits 0. The bare name `build.bat` is "not recognized" from PowerShell's cmd. The log stays empty until the run ends (~10 minutes), so confirm with `gh release list` afterwards.
- Releases must be non-draft and marked latest.
- On this host `build.bat release` does every platform: Windows locally, then `release_other_platforms()` in `tools/release.py` dispatches `.github/workflows/macos-release.yml` (Apple Silicon runner) and builds, lints and smoke-tests the `.deb` over `ssh root@serrebiradio.com` with `tools/build_deb_remote.sh` (debian:trixie containers, ~2 min; `LINUX_BUILD_HOST` overrides the host), uploads it and waits for the macOS zip. If that half fails after publishing, rerun it: `python -c "import sys; sys.path.insert(0, 'tools'); import release; release.release_other_platforms('X.Y.Z')"`. `debian-package.yml` no longer fires on a published release, so the host never builds the `.deb` twice. Never use `cloud-release.yml` from this host.
- Muse agent and cloud agents ONLY (never on this host, never while `build.bat release` runs; both bump from the latest tag): `.github/workflows/cloud-release.yml` runs the same `build.bat release` on a GitHub Windows runner (LFS checkout, Inno Setup, signed from the `WINDOWS_CODESIGN_PFX`/`WINDOWS_CODESIGN_PASSWORD` secrets, verified against that thumbprint), then dispatches `debian-package.yml` with `release_tag` (a release published with GITHUB_TOKEN starts no workflow) and checks the `.deb` and `/releases/latest`; one `macos-15` (Apple Silicon) job runs `tools/build_macos.sh` on the same commit and attaches `AccessibleIPTVClient-vX.Y.Z-macos-arm64.zip` (the script checks the bundled ffmpeg and libVLC work alone and that the app stays up 15 s). Translations: run `prepare-notes`, translate, and push ONLY the `locale/` changes to a scratch branch such as `release-notes/next`, never main; `-f translations_branch=<branch>` lays them over main uncommitted, as on the host. Delete the branch after the release. `gh workflow run cloud-release.yml -f dry_run=true` builds and prints the audit, publishing nothing. Watch with `gh run watch <id> --exit-status`. Use a `Changelog: skip` footer on CI-only commits.
- `cloud-release.yml`'s linux job must watch the debian-package.yml run it dispatched: it reads the run id from the URL `gh workflow run` prints, falling back to the dispatch whose run name is "Debian Package <tag>" (debian-package.yml `run-name`), so neither an older run nor a concurrent dispatch for another tag can be picked. `gh run list --limit 1` returned an older finished run for v1.145.1, so the job checked the release before the .deb was uploaded and reported a false failure on a complete release.
- Never delete old non-draft releases unless the user explicitly asks. It is okay to delete leftover draft releases.
- Never ship a release when PyInstaller reports unresolved warnings, missing imports, dependency mismatches, failed validation, or build errors.
- Do not bundle local `iptvclient.conf`. `main.spec` excludes it, and `tools/release.py` must fail the build if any packaged `iptvclient.conf` is found.
- `ffmpeg.exe` is tracked through Git LFS. Before releasing, ensure it is the real executable, not a small LFS pointer file. `tools/release.py` validates both the source and packaged `ffmpeg.exe` by size, pointer detection, and `ffmpeg -version`.
- `tools/release.py` runs PyInstaller through a limited Task Scheduler task when the current process is elevated, avoiding PyInstaller's elevated-token deprecation warning.
- `tools/release.py` creates the update manifest asset required by the auto-updater. Required manifest fields include `version`, `asset_filename`, `download_url`, `sha256`, and `release_notes_summary`.
- PowerShell/Batch release quoting matters on Windows. In batch files, `git describe --tags --abbrev=0` must be written as `--abbrev^=0` inside `for /f`. Inside a quoted `powershell -Command`, use a normal pipeline character (`|`), not `^|`.
- When cleaning GitHub draft releases from PowerShell, decode JSON first and filter explicit draft booleans with `Where-Object { $_.isDraft -eq $true }`; do not pipe raw JSON array output directly into a truthy object filter.
- A release run can die partway and leave the repo half-released. The window is between the commit and the tag in `git_commit_and_tag`: a `chore(release): vX.Y.Z` commit exists, but there is no tag, nothing is pushed, and there is no GitHub release, while the built and signed assets already sit in `dist/release/`. Diagnose with `git tag --list`, `gh release list`, and `git rev-list --left-right --count HEAD...origin/main`.
- Recover an aborted release by finishing it, not by repeating it. Re-running `build.bat release` fails by design in `update_changelog` with `CHANGELOG.md already contains vX.Y.Z`, and resetting the release commit only forces a rebuild that reproduces identical artifacts and re-signs them for nothing. Create the missing tag, then call `git_push` and `gh_release_create` from `tools/release.py` with the assets already on disk. The asset dict keys are `asset_path`, `latest_path`, `manifest_path`, `notes_path`, and `installer_path`; `gh_release_create` already calls `ensure_release_published_latest` and `delete_draft_releases`, so the published result matches a normal run. Only reuse assets whose manifest version and hashes match the current `HEAD`.

## Current Learnings

- Search results must be installed before focusing/selecting a result. `_VirtualChannelList.replace_contents()` clears selection even when the new row count is unchanged; focus alone leaves a one-result search with no selected channel and an empty URL. Select the first installed result only while the channel list has focus, preserving the search-focus generation guard. `tools/smoke_playlist_navigation.py` checks Sky Mix via Enter and Tab, then two Tabs to its URL.

- M3U and EPG display names are stored in `playlist_names` / `epg_names` mappings keyed by `playlist.source_name_key()` (SHA-256 of the original source). Keep source strings intact for existing loaders/caches. Provider names remain in their source dictionaries. Managers copy editable state so Cancel cannot change the live configuration; names are accepted with `GetNames()` alongside `GetResult()`.

- Playlist scope must include plain M3U URL/file strings using stable hashed IDs as well as provider IDs. Associate each completed playlist future with its actual source, and tag both cached and fetched channels; never use a leftover loop variable. Category counts and rows must use the scoped sources. The full browsing Tab cycle is Playlist view, categories, search, channels, on-air episode description, stream URL, reversed by Shift+Tab. The description comes before the URL and is always present; the URL field is optional and, when hidden, Tab from the description hands over to wx traversal so it wraps. Never point a Tab handler at a control that may be hidden - SetFocus on a hidden window silently does nothing and strands the user. Never trap traversal in just the playlist/category/channel controls. Category Tab activates the category then focuses search; Enter activates and focuses channels. Run `tools/smoke_playlist_navigation.py` after changing this wiring.

- On Python 3.14, `platform.system()` can fall back to a subprocess on Windows. Do not call it at module import time; use `sys.platform` for import-time OS detection so importing `main.py` remains subprocess-free.
- In the current Windows tooling, plain `rtk pytest ...` can incorrectly report that no tests were collected, while direct RTK passthrough invocations can surface a false nonzero wrapper status after a passing run. Use `rtk proxy cmd /d /c "python -m pytest ... & echo PYTEST_EXIT:%ERRORLEVEL%"` and require both pytest's pass summary and `PYTEST_EXIT:0`.
- If `.pytest-work` is left inaccessible after an interrupted elevated Windows test run, do not reuse it: pytest now uses the ignored `.pytest-runs` workspace-local base temporary directory. This avoids broken ACL cleanup while retaining the `conftest.py` suppression of Python 3.14's relative `*current` links.
- Windows installer builds use Inno Setup with a `.windows-installed` marker in Program Files. Installed/runtime mutable state belongs under `%APPDATA%\AccessibleIPTVClient`; Program Files should contain only application binaries and bundled assets, and installed auto-updates should use the signed setup EXE rather than replacing Program Files directly.
- `wx.LogError` uses printf-style formatting. Escape literal percent signs before passing user/provider text into it.
- `sitecustomize.py` must remain a shim. The internal player implementation belongs in `internal_player.py` only.
- Startup must stay lazy: do not run FFmpeg probes/installs, import casting stacks (`casting`, `caster_engine`, `pychromecast`, `pyatv`), start the stream proxy/firewall rule, or import the built-in VLC player during `main.py` import or `IPTVClient.__init__`. Initialize those only when recording, casting, or built-in playback is actually requested.
- EPG auto-import should be based on usable joined EPG data and source freshness, not just the presence or mtime of `epg.db`. `_ensure_db_tuned()` must not create an empty placeholder database.
- XMLTV reimports must replace stale titles and overlapping programme slots for the same channel ID. A correct feed on tv.serrebiradio.com was still shown as unrelated shows because the old `insert_programme` upsert changed only descriptions; 74 of 145 live Sky channels disagreed with the local database on 2026-09-27. An import lock with a dead owner PID must be reclaimed promptly rather than waiting two hours.
- EPG matching must account for country-specific channel aliases and suffixes, especially AU/CA/IE/UK/US sources. IPTV-org style XMLTV IDs with `@` suffixes need expansion for better channel matching.
- XMLTV downloads can resume, but HTTP 416 means the local partial file is already complete or invalid for that source; the downloader has fallback logic for this and should keep it.

- **urllib sends no `Accept-Encoding`, so an EPG feed arrives uncompressed unless we ask.** tv.serrebiradio.com (Dispatcharr) gzips `xmltv.php` *only* when the client sends `Accept-Encoding: gzip`; without it the response is 542 MB of plain XML, `Transfer-Encoding: chunked` with **no Content-Length**, which took ~54 s and reliably died mid-transfer with `[WinError 10054]`. Adding the header gives 44 MB in ~9.5 s (12.2x), same payload. Note the importer's `is_gz` check does see `Content-Encoding: gzip` and wraps the response in `gzip.GzipFile`, so no other change was needed - the robust resume/temp-file path is still keyed on the `.gz` *suffix* only, which this URL does not have. Keep the header on every EPG request, not just this source.

Arming while something is already running or queued adopts that work; arming with nothing running waits for the next recording to start. It also waits for scheduled jobs, disarms itself once used or canceled, and its countdown dialog is created with no parent, because the main window is usually minimized to the tray by then and a dialog owned by a hidden window never appears.
- Anything that closes the app on purpose has to set `_exit_forced` before `Close()`. `on_close` vetoes the close and hides to the tray whenever `minimize_to_tray` is on, which would otherwise leave the app running through its own shutdown request.
- A test run that finishes green and then appears to hang is wx waiting for a click. Tests exercise failure paths on purpose -- `test_add_provider_source_survives_a_dialog_that_cannot_open` feeds in a dialog class that raises -- and the production code answers with `wx.LogError`, whose default target under a GUI app is a *modal message box*. The box is queued, surfaces at interpreter shutdown with no event loop behind it, and blocks the process until someone dismisses it. From a terminal it looks exactly like an infinite hang: the suite reports all tests passed, then nothing. With a screen reader the stray dialog is worse than the delay. `tests/conftest.py` redirects wx logging to `wx.LogStderr`, which took the full run from 36s to 15s with a clean exit 0.
- Setting that log target once at session start is not enough: constructing `wx.App` installs wx's own GUI target and discards ours, so conftest re-checks it before every test body (a `pytest_runtest_call` wrapper, which runs after fixtures have built the app). `test_wx_errors_are_not_shown_as_modal_dialogs` asserts the redirect survived. Never restore the previous target afterwards: `wx.Log.SetActiveTarget` takes ownership of what it is given and deletes what it returns, so handing the old pointer back at teardown is a use-after-free that kills the interpreter with a Windows access violation.

- The Windows installer's `[InstallDelete] Type: filesandordirs; Name: "{app}\_internal"` wipes the PyInstaller runtime before the new files land, so for the length of the install the installed exe cannot start at all: it dies with "Failed to load Python DLL ...\_internal\python314.dll". The app is already closed by then, so the obvious user reaction - clicking the shortcut again - lands exactly in that window. `_warn_update_is_installing()` says so *before* the helper is launched (the helper only waits 30 seconds for our PID to exit), and `updater.write_update_pending()` drops a marker in the per-user config directory - not the install directory, which is what gets replaced - so `_report_finished_update()` can report on the next start whether the update landed.
- Every `wx.MessageBox` in `main.py` must go through the module-level `message_box()` wrapper. The "second box inside the first box's message loop leaves the main window permanently disabled" bug is only avoided if the deferral guard knows a box is up, and it cannot know that for boxes opened with a bare `wx.MessageBox` (which is how `_stop_recording_for_channel` reopened the bug after the first fix). `message_box()` keeps an app-wide depth and fires `set_modal_box_closed_hook()` when the last box closes, which is what drains the queued notifications.
- Binding `EVT_CHAR_HOOK`/`EVT_KEY_DOWN` on a control to add one key's behaviour must `event.Skip()` for every other key. The About dialog's hyperlinks opened the browser from an unconditional handler, so Tab (and each arrow key) launched a browser window while merely moving through the dialog. Note also that `wx.WXK_MENU` is Alt; the Applications key is `wx.WXK_WINDOWS_MENU`.
- A `wx.Dialog` consumes Enter before the focused control sees an `EVT_KEY_DOWN`, so Enter handlers on a list inside a dialog must use `EVT_CHAR_HOOK` (or a real default button). `CatchupDialog` had `EVT_KEY_DOWN` and no default button, so Enter on a catch-up programme did nothing at all.
- `get_config_read_candidates()` leads with `_config_write_target(create=False)`. Read order and write target used to be derived independently, and a portable build unpacked into a read-only folder read from the app directory while saving to `%APPDATA%` - so every settings change (a renamed playlist, say) reverted at the next start. `_config_write_target` takes `create` because `tests/test_startup_lazy.py` asserts that computing the read candidates does not create the user config directory.
- wxMSW gives a freshly shown dialog's focus to the first control in tab order, and a `SetFocus()` in the constructor does not survive that. `_SourceNamesMixin._focus_source_list()` therefore also queues a `wx.CallAfter`, which runs once the modal loop is up.
- Do not put backslash escapes (`\t`, `\n`) inside a bash heredoc that feeds a Python patch script in this environment: they arrive as real tabs/newlines and silently corrupt the patched source. Build them as `chr(92) + "t"` or write the script to a file first.
- libVLC's `stop()`, `player.release()` and `instance.release()` are synchronous: they wait for the demuxer and the HTTP access thread to unwind. Closing the built-in player ran all of them on the GUI thread, so with the machine busy - an EPG import saturating disk and network is the reported case - the message pump stopped and the whole app went unresponsive, greyed out to Windows and silent to NVDA. `_exit_player` now hides the frame, tells the app it has closed, and runs `_release_vlc` on a worker thread; `_finish_destroy` destroys the wx frame afterwards, because VLC must let go of the video panel before wx destroys it. `Destroy()` and a non-vetoable `_on_close` join that worker (bounded by `_VLC_TEARDOWN_JOIN_SECONDS`) before letting the destruction through. `_release_vlc` is idempotent, so the two paths cannot double-release.
- A long background job with no window of its own must report its own completion. `File > Import EPG to DB` promised "will start in the background" and then never spoke again. `start_epg_import_background` now returns whether it actually started and takes `notify=`; only the hand-started import sets it, so the periodic automatic refresh stays silent instead of stealing focus. The completion box goes through `_show_or_queue_message_box`, and is shown *after* `on_highlight()` so the reloaded guide is already behind it.
- F1 context help is wired once, on the `wx.App`, by `main.install_help_hooks`: an app-level `EVT_CHAR_HOOK` (the last stop of any unhandled key, in every window) and `EVT_HELP`. On Windows one F1 press arrives as *both*: the char hook fires, and even when it consumes the key Windows still sends `WM_HELP`, which wx turns into `EVT_HELP` for the focused control. `request_context_help` therefore drops a second request within 0.5 s. With a menu open there is no char hook at all, only `EVT_HELP`, whose event object is the menu's window (the frame, or the control a popup menu was shown on) and whose id is the *highlighted item's* id - that is how menu items get their own topics. That id comes from `HELPINFO.iCtrlId` as an unsigned 16-bit number: wx's automatic (negative) item ids arrive as 65536 minus the id (-31992 becomes 33544), so `user_guide.topic_for_menu_item` tries both forms. The menu must be closed *after* the `WM_HELP` handler returns (`wx.CallAfter` → `user32.EndMenu()`): a popup (context) menu ignores `EndMenu` called from inside the handler, stays in menu mode, and a guide opened then sits inside the popup's modal loop where Escape and every other key still go to the menu. `_show_when_menus_closed` also waits until `GetGUIThreadInfo` clears `GUI_INMENUMODE`/`GUI_POPUPMENUMODE` before opening the guide. `tools/smoke_user_guide_f1.py` drives all of this with real key presses. The app char hook runs before menu-bar accelerators, so `User Guide\tF1` on the Help menu shows the shortcut without stealing F1 from context help; a real click on the item (F1 not held) opens the guide at its start. Linux sends no `WM_HELP`; the char hook covers F1 there.
- The User Guide text box must be `TE_RICH2`. Its caret positions equal Python string offsets; a plain multiline EDIT counts each `\n` as two positions, so section jumps and Find selections land early by one character per line above them. Find lower-cases with a length-preserving fold (`str.lower()` turns a Turkish dotted capital I into two code points).
- A stream URL may carry an M3U `|Key=Value` tail, and `_build_generic_catchup_url` re-attaches the channel's `|User-Agent=` to every template-style (`catchup="append"`) catch-up URL. Players parse that tail; HTTP does not - it lands in the query string. `_begin_catchup_download` therefore splits it off with `http_headers.split_stream_modifiers` and merges the result into the channel headers before probing, or the `index-<utc>-<duration>.mp4` probe always fails and the download silently falls back to the HLS playlist, which arrives at playback speed instead of line speed. `internal_player._parse_stream_modifiers` delegates to the same function so the two cannot drift.
- Some catch-up providers (teleelevidenie observed) close the HTTP connection part-way through a direct `index-<utc>-<duration>.mp4` file. FFmpeg treats the truncated read as normal EOF and exits 0, so a 30-minute download can end at 18:26 and be reported as complete. `recorder.py` captures the last `time=` stats line as `media_written_seconds` on finish, and main.py's truncation check (`_catchup_download_is_truncated`, default 10% shortfall tolerance) compares it against the requested window; short-but-clean downloads are deleted and re-queued through the existing catch-up retry flow (the `.part` rename has already happened by then, so delete the final file only when a retry was actually scheduled), and an exhausted budget gets an honest "Download ended early" box instead of "complete".
- Catch-up downloads apply the configured pre/post schedule-padding minutes through `_padded_catchup_window()`, unlike the old programme-exact window. The direct-file probe tries the padded window first and falls back to the programme-exact file, because some providers store only exact-programme MP4s. Availability/on-air checks must stay on the exact programme window: resolving availability from the padded window would misclassify a just-finished programme as still on air.
- Filling `.po` translations programmatically: parse the PO blocks yourself and write with `newline=""` so the LF-only files stay LF (Windows text mode churns every line to CRLF). Split long msgstrs into `msgstr "..."` + continuation `"..."` lines, escaping `\n` as literal backslash-n. `tools/i18n_tools.py update` re-normalizes to LF afterwards, so a quick `update` + `compile` also heals a CRLF accident.
- Hungarian review issues from @htibcsike can arrive in rounds inside one issue: an interim comment supersedes the original body, then the body itself is edited last with a closing comment saying to use it. Compare the issue's `updatedAt` against the comment timestamps and treat the *last-edited body* as authoritative, not the first text or the interim comments. When such a review claims an English-source/behaviour mismatch (issue #20, recording-log bullet), verify the claim against the actual code path before touching `docs/help/en.md`; `en.md` is the reference `hu.md` mirrors, so fix the English first and keep both in step.
- Scheduler-thread notifications, including “Scheduled recording started”, must use `IPTVClient._show_or_queue_message_box()` through `wx.CallAfter`, never `message_box()` directly. A direct app-modal box can arrive while the user is still dismissing the scheduling confirmation and freeze wxMSW by nesting its message loop. The scheduled-recordings `wx.ListCtrl` intentionally permits multi-selection: Ctrl+A selects every row; Delete and Numpad Delete are silent for an empty list, otherwise they confirm the selected title (or “all” only when every displayed row is selected); and active selected jobs are stopped before deletion.
- Main-window shortcut ownership is deliberate and regression-tested: `Ctrl+Shift+J` exclusively shows the already-loaded built-in player, while `Ctrl+Up`/`Ctrl+Down` control volume. Do not restore the dead legacy `Ctrl+Shift+J`/`Ctrl+Shift+K` volume bindings; the former silently stole the documented Show Player shortcut.
- Release notes are localized through gettext, never by translating `CHANGELOG.md` or mirroring it per language (issue #25). `release_notes.py` owns the section labels (`SECTIONS`: Breaking changes, Features, Accessibility, Bug fixes, Documentation, Other changes) and "No notable changes." as ordinary `iptvclient` strings, which must stay fully translated. Individual bullets live in the separate `release_notes` domain (`locale/release_notes.pot`, `locale/<lang>/LC_MESSAGES/release_notes.{po,mo}`), which is deliberately exempt from `test_shipped_catalogue_is_fully_translated`: translators fill it in after a release and untranslated bullets fall back to English. `i18n_tools.py notes` (also run by `all` and by `release.py sync_translations()` right after the CHANGELOG entry is written) extracts bullets from the newest three `## v` entries only (`RELEASE_WINDOW`/`NOTES_WINDOW`, agreed with @htibcsike: current plus previous two) and rewrites every language's `release_notes.po`, keeping translations of bullets still in the window and retiring the rest. `release.py` now writes CHANGELOG entries with `### <label>` groups and cleaned, de-duplicated bullets, and the GitHub body/manifest summary uses the same English labels; `ChangelogDialog` shows `release_notes.localize_changelog()` (translated intro replaces the maintainer preamble) and the update prompt uses `localize_notes(clean=True)` for older bodies with `fix:`-style prefixes. The update prompt can only translate labels for a new release, because the running app's catalogue predates its bullets.
- `classify_commit()` must never substring-search the commit **body**. An `i18n(hu)` commit whose body honestly mentioned the section label "Breaking changes" was matched by the old `"breaking change" in text` check, classified Breaking, and released as v2.0.0 within minutes (0 downloads; deleted, main rewound past `chore(release): v2.0.0`, re-released as v1.136.1). Breaking is now subject `type!:` or a real `BREAKING CHANGE:`/`Breaking changes:` footer only; `fix`/`feature`/`bug` matches read the subject alone. Regression tests pin this in `tests/test_release.py`. Never write a section label verbatim in a commit body on this repo until that rule is second nature.
- The update helper's status window must manage focus, not just visibility (issue #30): when the app closes, focus falls to the desktop, and when the UAC prompt returns, focus goes back to the app that just exited - the TopMost status window was still on screen but to NVDA it had disappeared. `update_helper.ps1` now calls `Focus-StatusWindow` once when the parent process exits and once per `Update-StatusMessage` stage change (each grab makes NVDA read the new window title), while `Watch-StatusWindowFocus` (called from `Wait-Pumped`) latches `UserLeftStatusWindow` the moment `GetForegroundWindow` reports any other window, after which the update never takes focus back - the stage text still updates in the title for NVDA+T. A NULL foreground is the UAC secure desktop and never counts as the user leaving. Focus watching only starts after the first successful grab, or the app's own still-open progress dialog would be mistaken for the user switching away. The helper is staged from the *installed* build, so a helper fix only takes effect from the update after the one that ships it.
- Not every foreground change during an update is the user leaving (follow-up to #30). The silent installer's hidden windows take the foreground when it starts, and on Windows 11 the foreground can also stay parked on Explorer's invisible `ForegroundStaging` window; both used to latch `UserLeftStatusWindow`, so the status window was never re-focused, NVDA went silent for the install, and because the helper was no longer foreground the restarted app could not take focus and its "Update Complete" box went unread. `Get-ForegroundOwnerKind` now sorts the foreground into self / update (installer PID and its children, tracked in `$script:UpdateOwnedPids`) / neutral (no window = secure desktop, `consent.exe`, desktop, taskbar) / transient (`ForegroundStaging`, taken back after `TransientGraceMs`) / other (only this latches). Watching starts only once the window really held the foreground, `ForceForeground` uses `AttachThreadInput` when a plain `SetForegroundWindow` is refused, and `Grant-ForegroundToNextProcess` runs before the app is restarted. The "Windows will ask for permission" stage is shown only when `Test-ElevationPromptExpected` says a prompt will appear (EnableLUA, token elevation type, ConsentPromptBehaviorAdmin/User); UAC off or "elevate without prompting" announced a prompt that never came. This dev machine has `ConsentPromptBehaviorAdmin=0`, so an end-to-end run of the helper against the real installer with `/DIR` in %TEMP% and a dummy parent PID reproduces that setup; the log names every window that took the foreground.
- The app owns the cancellable download in one `wx.ProgressDialog`. Only after the installer is fully downloaded and verified does it launch `update_helper.ps1`, replace the dialog with a non-cancellable handoff message, and wait for the helper's `update_window_ready` marker before closing. Starting the helper before the download left both the helper and app windows alive and could strand keyboard focus between them. Keep the helper's current focus recovery, result reporting, and restart logic; only the download-to-helper handoff returned to the proven two-stage flow.
- **The status window used to be created invisible.** `updater.popen_hidden` passes a STARTUPINFO with `wShowWindow = SW_HIDE`, and Windows applies that to the *first top-level window the process shows*, not just to a console - so the helper's WinForms window existed, with the right title, but `IsWindowVisible` was false until something forced it to the foreground. That only happened after the app had exited, which is exactly the reported "the update window disappears at Preparing the update": for the whole of that step there was nothing on screen. `launch_update_helper` now passes `_no_show_startupinfo()` (CREATE_NO_WINDOW still keeps the console away) and `Show-UpdateStatus` calls `ShowWindow(SW_SHOWNORMAL)` itself. Never launch the helper through plain `popen_hidden` again.
- The window holds its controls in `$script:StatusLabel`/`StatusProgress`/`StatusButton`, never `$form.Controls["StatusLabel"]`: that lookup returned null on a user's machine (issue #31 logged "The property 'Text' cannot be found on this object"), and because it threw on the first line of `Update-StatusMessage`, the title stopped updating and the window sat on one message for the rest of the update. `Get-StatusWindow` re-creates the window if it is ever lost, and `ControlBox = $false` plus a `FormClosing` handler mean neither Alt+F4 nor anything else can take it away while the update runs. The one button it ever shows is Cancel during the download and Close on a failure.
- Inno Setup must not close applications itself (`CloseApplications=no`, issue #31). With the default `yes`, Restart Manager reported the update helper's own Windows PowerShell as "an application using one of our files", could not shut it down - it is the process driving Setup - and the `/SUPPRESSMSGBOXES` default for that prompt is Abort, so every install rolled back with exit code 5. `CloseApplications=force` would be worse: it would terminate the helper mid-update. The updater already closes the app and kills anything left running from the install directory.
- `tools/smoke_update_window.py` drives the real window through both halves of a real update (download with Cancel, then the hand-over to the install) and checks what pytest cannot see: that it appears at all, that the title follows every step, that it survives the app closing, and that it refuses to close. Run it after touching `update_helper.ps1` or the session protocol. Everything it starts besides that window is windowless on purpose - a console stand-in for the app stole focus from whoever was running it.
- The status window is now up while the app is still usable (it covers the download), so `Watch-StatusWindowFocus` can latch `UserLeftStatusWindow` on the *app itself*: someone who goes back to watching television during a 95 MB download used to disable every later re-focus, and NVDA then had nothing for the whole install. `Reset-StatusFocusLatch` reopens it at each moment the update becomes the user's task again - the install starting, a failure, a stop, and the final confirmation - and nowhere else, so a progress message still never pulls focus away mid-download.
- `Write-UpdateSuccess` must run **before** `Start-AppAfterUpdate`, not after. The restarted app reports the update about 50 ms after it shows its window, while the restart check deliberately blocks for five seconds proving the new process survived; a result written after that race was lost, `read_update_result()` returned None, and the new version opened its own "successfully updated" box on top of the update's own window - the box this window exists to replace.
- A restart that never worked is not a completed update: `Complete-SuccessfulUpdate` takes `-Restarted` and, when it is false, says the update is installed but the app could not be started (`restart` message) instead of "Update complete", and records nothing for the app to read.
- Anything that gives up on a live helper must stop it (`_stop_update_helper`). Its window has no close button and cancels `FormClosing` by design, and it waits for an instruction that is never coming, so an abandoned helper leaves an always-on-top window the user cannot get rid of without Task Manager. For the same reason `_discard_update_download` takes the helper handle from its caller: `_abort_update_window` ends the flow on the GUI thread, which clears `self._update_helper`, and the folder being deleted is the one holding the running `update_helper.ps1` and the message it is about to show.
- **Never synthesise an Alt keypress to take the foreground.** `_force_foreground` used `keybd_event(VK_MENU, ...)` - the well-known trick for unlocking `SetForegroundWindow` - and Alt is also what opens a menu bar, so the app pressed Alt for the user and left them in the menu instead of the channel list: at the end of every update, on every restore from the tray, and every time a second copy brought the running one to the front. `AttachThreadInput` (already there) is what actually grants the right; a test pins `keybd_event` out of main.py for good.
- A finished update takes its window away: `Complete-SuccessfulUpdate` says the update is complete, pauses `$script:CompleteLingerMs` for that to be spoken, hands the foreground to the restarted app and closes. No Close button - the update is over, and a button there is one more thing between the user and the application. Only the paths that have something to read keep `Wait-ForDismissal`: a failed or cancelled update, and an install whose app would not start.
- One copy per user (`single_instance.py`, named mutex `Local\AccessibleIPTVClient-single-instance`, flock elsewhere). Two copies share the config, EPG DB, log and DVR schedule with nothing coordinating them: with minimize-to-tray on, Alt+F4 only hides the app, so reopening it started a second copy, both schedulers started the same Teleelevidenie recording seconds apart, the second got 403 (ffmpeg rc 3436169992) and the provider then dropped the first (rc=1). - Brief live audio cut-outs with no "Reconnecting" in the log are libVLC rebuffers.
